# Исправление ошибки HACS "version can not be used"

## Проблема

HACS показывает ошибку:
```
The version a86d707 for this integration can not be used with HACS.
```

Это означает, что HACS не может определить версию интеграции.

## Решение

HACS определяет версию из **Git tags**. Нужно создать тег с версией.

### Шаг 1: Создайте Git tag

```bash
# Создайте тег с версией (формат: v1.0.0, v1.0.1 и т.д.)
git tag v1.0.0

# Загрузите тег в удаленный репозиторий
git push origin v1.0.0

# Или загрузите все теги сразу
git push --tags
```

### Шаг 2: Обновите репозиторий в HACS

1. В HACS перейдите в **Интеграции**
2. Найдите вашу интеграцию **Grand Meyer SMM-9000**
3. Нажмите **Перезагрузить** (если доступно)
4. Или удалите и добавьте репозиторий заново

### Шаг 3: Проверьте версию

После создания тега HACS должен показать версию `1.0.0` вместо hash коммита.

## Версионирование для будущих обновлений

Для каждого нового релиза создавайте новый тег:

```bash
# Для патч-релиза (исправления)
git tag v1.0.1
git push origin v1.0.1

# Для минорного обновления (новые функции)
git tag v1.1.0
git push origin v1.1.0

# Для мажорного обновления (breaking changes)
git tag v2.0.0
git push origin v2.0.0
```

## Альтернативное решение (не рекомендуется)

Если по какой-то причине вы не можете использовать Git tags, можно создать файл `info.md` в корне репозитория, но это не стандартный способ и может не работать.

## Проверка

После создания тега проверьте:

1. Тег виден в GitHub/GitLab: `https://github.com/your-username/ha-smm-9000/tags`
2. HACS показывает версию вместо hash коммита
3. Интеграция устанавливается через HACS без ошибок

## Примечания

- Версия в `manifest.json` должна совпадать с версией в Git tag (без префикса `v`)
- Формат тега: `v1.0.0` (с префиксом `v`)
- Формат версии в manifest.json: `1.0.0` (без префикса `v`)
